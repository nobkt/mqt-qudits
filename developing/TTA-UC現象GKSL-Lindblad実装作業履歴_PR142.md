### 分析結果サマリ

#### 完全理論書より抽出した主要要件

1. **GKSL-Lindblad Master Equation**

   ```
   dρ/dt = -i/ℏ[H, ρ] + Σ_α γ_α D[L_α][ρ]
   ```

2. **TTA-UC 4段階プロセス**

   - 増感剤の光吸収 → S₁ → T₁（ISC）
   - 三重項エネルギー移動: T₁(増感剤) → T₁(消滅剤)
   - 三重項-三重項消滅: T₁ + T₁ → S₁ + S₀
   - アップコンバージョン蛍光: S₁ → S₀ + 高エネルギー光子

3. **3準位分子状態（qutrit）**

   - |0⟩ = |S₀⟩: 基底状態 (0 eV)
   - |1⟩ = |T₁⟩: 三重項 (1.5 eV)
   - |2⟩ = |S₁⟩: 一重項 (3.0 eV)

4. **6つの実装シナリオ**

   - シナリオ1: 古典・ボソン無し
   - シナリオ2: 古典・ボソン有り
   - シナリオ3: Qubit・ボソン無し
   - シナリオ4: Qubit・ボソン有り
   - シナリオ5: Qudit・ボソン無し（MQT-Qudits中核）
   - シナリオ6: Qudit・ボソン有り

5. **厳密な数学的制約**
   - トレース保存: |Tr[ρ] - 1| < 10⁻⁸
   - 正定値性: λ_min ≥ -10⁻¹⁰
   - エントロピー増大: dS/dt ≥ -10⁻⁸
   - 粒子数保存: N_S0 + N_T1 + N_S1 = N_molecules

#### 実装詳細仕様書より抽出した主要要件

1. **26個のLindblad演算子**

   - TTA: 6個（3ペア × 2チャネル）
   - 蛍光: 4個
   - 燐光: 4個
   - 内部変換: 4個
   - ISC S→T: 4個
   - ISC T→S: 4個

2. **物理パラメータ**

   ```python
   E_T = 1.5 eV
   E_S = 3.0 eV
   V = 0.1 eV
   gamma_TTA = 0.05 eV/ℏ
   Gamma_fl = 0.01 eV/ℏ
   Gamma_ph = 1e-6 eV/ℏ
   k_IC = 0.005 eV/ℏ
   k_ISC_ST = 0.003 eV/ℏ
   k_ISC_TS = 1e-5 eV/ℏ
   ```

3. **統一出力データ構造**

   ```python
   {
       'times': List[float],
       'populations': List[Dict],  # N_S0, N_T1, N_S1
       'per_molecule_populations': List[Dict],
       'entropy': List[float],
       'purity': List[float],
       'trace': List[float],
       'rho_final': np.ndarray,
       'elapsed_time': float,
       'method': str,
       'params': dict
   }
   ```

4. **Stinespring Dilation**

   - 非ユニタリLindblad演算子をユニタリ演算に変換
   - 補助系（環境）の導入: 各演算子に1 qubit
   - 部分トレースによるシステム密度行列の復元

5. **2次Trotter分解**
   ```
   exp(L dt) ≈ exp(L_H dt/2) exp(L_D dt) exp(L_H dt/2)
   ```

#### 詳細設計書より抽出した主要要件

1. **クラス設計**

   - `GKSLPhysicalParameters`: パラメータ管理・検証
   - `ClassicalGKSLSimulator`: 古典ODE積分
   - `QubitGKSLSimulator`: Qiskit実装
   - `QuditGKSLSimulator`: MQT-Qudits実装
   - ボソン有り版: 各シミュレータの拡張

2. **超演算子構築（古典シミュレーション）**

   ```
   L_total = L_H + L_D
   L_H = -i/ℏ (H ⊗ I - I ⊗ H^T)
   L_D = Σ_α (L_α ⊗ L_α* - ½(L_α†L_α ⊗ I + I ⊗ L_α†L_α^T))
   ```

3. **量子回路構成（Qudit）**

   - システム: 4 qutrits
   - 補助系: 26 qubits
   - ハミルトニアンユニタリ: ~50ゲート
   - Lindblad回路: ~26×6 = 156ゲート
   - 1Trotterステップ合計: ~250ゲート

4. **検証パイプライン**

   - 各時間ステップで7項目チェック
   - 異常時はPhysicsViolationError例外
   - fallback処理は一切禁止

5. **8つのテストケース**
   - T1: ユニタリ極限（γ=0）
   - T2: 蛍光のみ（指数減衰）
   - T3: TTA主導（N_T1減少）
   - T4-T5: 数学的整合性
   - T6-T7: シナリオ間一致
   - T8: 長時間緩和

## 設計上の重要な決定事項

### 1. fallback処理の完全排除

**決定**: 数値誤差の「修正」や「強制正規化」を一切行わない

**理由**:

- ごまかしのためのヒューリスティック処理は禁止（要件）
- 数値誤差が大きい場合は実装エラーを疑うべき
- 物理的に不正な状態を隠蔽するリスク

**実装方針**:

- 全ての検証で異常時は例外を発生
- 許容誤差内の微小な数値誤差のみ許容
- 許容誤差: 1e-8（トレース）、1e-10（Hermitian性）、-1e-10（正定値性）

### 2. 統一出力データ構造

**決定**: 既存ノートブックとの完全な後方互換性を維持

**理由**:

- 既存の可視化関数を再利用可能
- ユーザーの既存コードが動作する
- 比較が容易

**実装方針**:

- 既存フィールドはそのまま
- GKSL固有の情報（entropy, purity等）を追加
- 'method'フィールドでシナリオを識別

### 3. モジュール分割戦略

**決定**: 機能ごとに明確にモジュールを分割

**理由**:

- 保守性の向上
- テストの容易性
- 再利用性

**モジュール構成**:

- パラメータ: `gksl_physical_parameters.py`
- 数学関数: `gksl_math_utils.py`
- Stinespring: `stinespring_utils.py`
- 検証: `gksl_validation.py`
- シミュレータ: 各シナリオ1ファイル
- 可視化: `gksl_visualization.py`
- テスト: `test_gksl_simulators.py`

### 4. 優先度順実装

**決定**: Classical → Qudit → Qubit の順で実装

**理由**:

- Classicalが基準実装（検証用）
- QuditがMQT-Quditsの中核機能
- Qubitは比較用

**実装順序**:

1. シナリオ1（Classical NB）: 基準
2. シナリオ5（Qudit NB）: 中核
3. シナリオ3（Qubit NB）: 比較
4. シナリオ2,4,6（ボソン有り）: 拡張

## 技術的課題と対策

### 課題1: 超演算子のメモリ使用量

**課題**: 6561×6561行列（約400MB）

**対策**:

- N_molecules=4に限定（仕様通り）
- スパース行列の検討（将来）
- 量子シミュレータへの移行推奨（N>4の場合）

### 課題2: Stinespring回路の最適化

**課題**: 26個の補助qubitで回路が大きい

**対策**:

- 疎行列構造を利用した効率的分解
- IntegratedSparseCompilerV2の活用
- ゲート数削減の工夫

### 課題3: Trotter誤差

**課題**: 2次Trotterで誤差O(dt³)

**対策**:

- 十分小さいdtの使用（dt = t_max/100）
- 誤差見積もりの明示
- 必要に応じて高次Trotter（将来）

### 課題4: MQT-QuditsとQiskitの統合

**課題**: 異なるフレームワークの統合

**対策**:

- 統一インターフェースの設計
- 出力データ構造の標準化
- フレームワーク依存部分の明確な分離
