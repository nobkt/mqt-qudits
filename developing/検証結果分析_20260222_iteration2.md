## 問題の詳細分析

### 1. 失敗する2シナリオの共通点

`classical` と `unitary` の両シナリオは共に `ClassicalGKSLSimulator` を使用している。

- `classical`: `ClassicalGKSLSimulator(params)` で直接実行
- `unitary`: `ClassicalGKSLSimulator(params_unitary)` で散逸率をすべて0に設定して実行

### 2. 根本原因: `solve_ivp(RK45)` によるCPTP構造の非保存

`ClassicalGKSLSimulator.simulate()` は `scipy.integrate.solve_ivp` を `method="RK45"` で使用してGKSLマスター方程式を数値積分している。

```python
sol = solve_ivp(
    ode_func,
    [0, t_max],
    y0,
    t_eval=t_eval,
    method="RK45",
    rtol=1e-9,
    atol=1e-12,
)
```

**RK45（Runge-Kutta-Fehlberg法）の本質的限界:**

- RK45は汎用的な陽的ODE積分法であり、密度行列のCPTP（Completely Positive Trace Preserving）構造を保存する機構を持たない
- GKSL方程式 `dρ/dt = -i[H,ρ] + Σ_α D[L_α](ρ)` の形式的解 `ρ(t) = exp(Lt)ρ(0)` は常にCPTPだが、RK45による近似解はこの性質を保証しない
- 数値誤差が密度行列の固有値にO(1e-10)の負値を導入する
- これは「数値精度の限界」ではなく、**積分手法の構造的問題**である

### 3. 成功するシミュレータとの根本的な相違

#### Qubit/Quditシミュレータ（成功）

`QubitGKSLSimulator`/`QuditGKSLSimulator` は **Stinespring dilation + 2次対称Trotter分解** を使用:

```python
def _trotter_step(self, rho, dt):
    # ハミルトニアン半ステップ: ρ → U ρ U† (ユニタリチャネル、常にCPTP)
    rho = self._apply_hamiltonian_step(rho, dt / 2)
    # 各Lindbladチャネル: Stinespring拡張 (常にCPTP)
    for L_op, _gamma in self.lindblad_ops:
        rho = self._apply_lindblad_stinespring(rho, L_op, dt)
    # ハミルトニアン半ステップ
    rho = self._apply_hamiltonian_step(rho, dt / 2)
    return rho
```

- **ハミルトニアンステップ**: `expm(-iHdt)` による正確なユニタリ発展 → CPTPチャネル
- **Lindbladステップ**: Stinespring拡張ユニタリ + 部分トレース → CPTPチャネル
- CPTPチャネルの合成は常にCPTP → **正値性が構造的に保証される**

#### Classical Bosonシミュレータ（成功）

`ClassicalGKSLBosonSimulator` も `solve_ivp` を使用するが、`method="BDF"`（陰的法）を使用し、かつシステムが小さい（N=2、dim_total=36）:

- BDFは陰的法でありRK45より数値安定
- 小システムのため数値誤差が蓄積しにくい
- フォノン自由度の部分トレースが小さな負の固有値を平滑化

### 4. Unitaryシナリオの問題

Unitaryシナリオは全散逸率を0に設定するため、純粋なハミルトニアン発展になる:

`dρ/dt = -i[H, ρ]`

この場合の正確な解は `ρ(t) = U(t)ρ(0)U†(t)` であり、密度行列の性質は完全に保存されるはずだが、RK45での近似積分が正値性を破壊している。

- 固有値: -2.25e-10（閾値 -1e-10 を超過）
- ユニタリ発展すら正しく積分できていない

## 修正方針

### 方針: ClassicalGKSLSimulatorのStinespring+Trotter化

`ClassicalGKSLSimulator` の `simulate()` メソッドを、`QuditGKSLSimulator` と同じStinespring dilation + 2次Trotter分解に置換する。

**これはヒューリスティックでもfallbackでもない:**

1. Stinespring+Trotterは量子チャネルの標準的な分解手法
2. Lindbladマスター方程式の各項を個別にCPTPチャネルとして正確に適用する
3. 2次Trotter誤差はO(dt²)で制御可能
4. 既にQubit/Quditシミュレータで正常動作が検証済み

### 具体的な修正内容

1. `classical_gksl_simulator.py`:
   - `solve_ivp` による積分を削除
   - `scipy.linalg.expm` と `stinespring_utils` をインポート
   - `_apply_hamiltonian_step()`, `_apply_lindblad_stinespring()`, `_trotter_step()` メソッドを追加
   - `simulate()` をTrotterループに変更

2. `unitary` シナリオは `ClassicalGKSLSimulator` を使用するため、自動的に修正される

### 修正しない項目

- `ClassicalGKSLBosonSimulator`: 現在PASSしているため変更不要
- `QubitGKSLSimulator` / `QuditGKSLSimulator`: 既に正常動作
- `gksl_validation.py`: 検証閾値は物理的に正当（-1e-10は妥当）
- ショット系シミュレータ: 既に正常動作

## 影響分析

### Classicalシミュレータの結果変化

修正後のClassicalシミュレータは、QuditGKSLSimulatorと同じStinespring+Trotterアルゴリズムを使用するため:

- Classical ≈ Qudit の結果（Trotter分解の実装が同一のため完全一致が期待される）
- min_eigenvalue ≈ -3e-16（浮動小数点誤差レベル、閾値-1e-10を大幅に下回る）
- 正値性、トレース保存、粒子数保存がすべて検証を通過する見込み

### Unitaryシナリオの結果変化

- 全散逸率0のため、Stinespring Lindbladステップは恒等写像
- 純粋ハミルトニアン発展のみ → `expm(-iHdt)` による正確なユニタリ発展
- 正値性が完全に保存される見込み
