## 発見された問題点

### 問題1（重大）: QubitGKSLSimulator ≡ QuditGKSLSimulator — 実質的に同一実装

**現象:**

| 指標 | qubit | qudit | 差異 |
|------|-------|-------|------|
| final_entropy | 0.030046553479 | 0.030046553479 | **完全一致** |
| final_purity | 0.992445599524 | 0.992445599524 | **完全一致** |
| pop_final S0 | 2.003864912176 | 2.003864912176 | **完全一致** |
| pop_final T1 | 1.992551974629 | 1.992551974629 | **完全一致** |
| pop_final S1 | 0.003583113195 | 0.003583113195 | **完全一致** |
| F(qubit, qudit) | **1.0000002065** | — | 数値誤差の範囲で完全一致 |

**根本原因:**

`QubitGKSLSimulator` と `QuditGKSLSimulator` はともに**同一の81次元キュートリット空間**で動作する。

- 同一のハミルトニアン `H_total`（81×81）を使用
- 同一のリンドブラッド演算子 `lindblad_ops` を使用
- 同一の `_trotter_step` アルゴリズム（Stinespring + 2次Trotter）
- 同一の `stinespring_unitary_from_lindblad` と `apply_stinespring_to_density_matrix`

`QubitGKSLSimulator` には `_embed_in_qubit_space()` と `_extract_from_qubit_space()` メソッドが存在するが、**simulate()メソッド内で一度も使用されていない**。結果として、qubitシミュレータは事実上quditシミュレータの名前変えにすぎない。

**理論的問題:**

量子ビット計算と量子ディット計算の本質的な違いは:

1. **符号化オーバーヘッド**: 各3準位分子を2量子ビットで符号化 → 4^N = 256次元空間（vs キュートリットの3^N = 81次元）
2. **禁止状態**: |11⟩状態はキュートリット符号化に存在しない物理的に無意味な状態
3. **ノイズモデル**: 量子ビットのパウリノイズ（d=2）vs キュートリットのWeyl-Heisenbergノイズ（d=3）
4. **リーケージ**: 量子ビットのパウリエラーは禁止状態|11⟩へのリーケージを引き起こす

これらの違いが反映されていないため、qubit vs quditの比較が無意味になっている。

**深刻度: 最高** — プロジェクトの根本目的（量子ビット vs 量子ディット比較）を損なう。

### 問題3（重大）: QubitGKSLNoisyShotSimulatorがd=3キュートリットノイズを使用

**現象:**

`qubit_noisy_shot` と `qudit_noisy_shot` は異なる結果を生成する（F = 0.9547）が、
この差異は**ノイズモデルの種類の違い**（脱分極+熱緩和 vs 脱分極+位相緩和）のみに起因し、
**符号化方式の違い**を反映していない。

**根本原因:**

`QubitGKSLNoisyShotSimulator._trotter_step_trajectory()` は以下のインポートにより
キュートリット空間のd=3ノイズを使用:

```python
from qudit_gksl_shot_simulator import (
    _apply_stochastic_depolarization_pair,   # d=3 Weyl-Heisenberg
    _apply_stochastic_depolarization_single,  # d=3 Weyl-Heisenberg
)
```

これは理論的に不正確:

- 量子ビットハードウェアのノイズはパウリ演算子（σ_I, σ_X, σ_Y, σ_Z）に基づく d=2 ノイズ
- 2量子ビット符号化では、パウリエラーが禁止状態|11⟩へのリーケージを引き起こす
- d=3 Weyl-Heisenberg脱分極はキュートリット空間内に留まりリーケージを生じない
- 量子ビットシミュレータがキュートリットノイズを使用することは物理的に不正確

**具体例: パウリXエラーによるリーケージ**

分子mの2量子ビット符号化: |00⟩=S0, |01⟩=T1, |10⟩=S1, |11⟩=禁止

- σ_X ⊗ I: |00⟩→|10⟩ (S0→S1), **|01⟩→|11⟩ (T1→禁止!)**, |10⟩→|00⟩, |11⟩→|01⟩
- I ⊗ σ_X: |00⟩→|01⟩ (S0→T1), |01⟩→|00⟩, **|10⟩→|11⟩ (S1→禁止!)**, |11⟩→|10⟩

16個の2量子ビットパウリ演算子のうち、8個がリーケージを引き起こす可能性がある。
このリーケージは量子ビット符号化固有の問題であり、キュートリット符号化では発生しない。

**深刻度: 最高** — ノイズモデルが量子ビットの物理を正しく反映していない。

### 問題5（軽微）: Classical vs Qubit/QuditのTrotter誤差

**現象:**

| シナリオ対 | Fidelity | エントロピー差 |
|-----------|----------|-------------|
| classical vs qubit | 0.999995 | 0.0306 vs 0.0300 (~1.7%) |
| classical_boson vs qubit_boson | 0.999905 | 0.722 vs 0.729 (~1.0%) |

**分析:**

これはTrotter分解の理論的近似誤差であり、コードのバグではない。
- Classical: 正確なリウヴィリアンexpm（厳密解）
- Qubit/Qudit: 2次Trotter分解（O(dt²)近似）
- dt = 1.0（t_max/n_steps = 5.0/5）は粗い時間刻み

n_stepsを増やすことで誤差は減少する（O(1/n_steps²)で収束）。

**深刻度: 低** — 理論的に期待される振る舞い。

## 修正方針

### 方針概要

全qubitシミュレータを**実際の量子ビット符号化空間**（4^N次元）で動作するように修正する。
これにより:

1. 量子ビットシミュレータがキュートリット空間ではなく量子ビット空間で計算
2. 禁止状態リーケージの検出・報告が可能
3. ノイズモデルが量子ビットハードウェアの物理を正しく反映
4. qubit vs quditの比較が物理的に意味を持つ

### 修正1: QubitGKSLSimulator — 256次元量子ビット空間での演算

**変更内容:**

1. `__init__`: ハミルトニアンとリンドブラッド演算子を256次元空間に埋め込み
2. `prepare_initial_state`: 初期状態を256次元空間で準備
3. `_trotter_step`: 256次元空間でTrotter演算
4. `simulate`: 各時間ステップで81次元キュートリット空間に抽出して観測量を計算
5. `check_forbidden_states`: 禁止状態リーケージを検査・報告

**数学的保証:**

ノイズなしの場合、256次元空間でのTrotter演算の結果を81次元に抽出した結果は、
81次元で直接計算した結果と数値精度の範囲で一致する。
これは演算子の埋め込みが物理部分空間を不変に保つため（forbidden状態はハミルトニアンにもリンドブラッド演算子にも結合しない）。

### 修正2: QubitGKSLShotSimulator — 256次元空間での量子軌道

**変更内容:**

1. 状態ベクトルを256次元空間で準備・発展
2. Stinespring拡張ユニタリを512×512空間で計算
3. 測定結果をキュートリット基底にマッピング

### 修正3: QubitGKSLNoisyShotSimulator — 量子ビットレベルパウリノイズ

**変更内容:**

1. d=3 Weyl-Heisenbergノイズを d=4 量子ビットパウリノイズに置換
2. 各分子の2量子ビットに対して σ_a ⊗ σ_b（16個のパウリ演算子）を適用
3. リーケージ（禁止状態|11⟩への遷移）を追跡・報告
4. 熱緩和ノイズも量子ビット空間で実装

**物理的効果:**

- 16個のパウリ演算子のうち8個がリーケージを生じうる
- リーケージ率は p_depol に比例
- リーケージにより実効的な情報損失が発生
- これは量子ビット符号化固有のオーバーヘッドであり、キュートリット符号化では存在しない

### 修正4: QubitGKSLBosonSimulator — 量子ビット符号化拡張空間

**変更内容:**

電子自由度のみを量子ビット空間に埋め込み（フォノン自由度は不変）。
拡張空間次元: 4^N × (n_max+1)^N（N=2, n_max=1で64次元）。

## 修正しない項目

- `ClassicalGKSLSimulator`: 独立参照解として正常動作（正確expm法）
- `ClassicalGKSLBosonSimulator`: 同上
- `QuditGKSLSimulator`: キュートリット空間での動作は設計通り
- `QuditGKSLShotSimulator`: d=3ノイズモデルはキュートリットとして正しい
- `QuditGKSLBosonSimulator`: 設計通り
- `gksl_math_utils.py`, `gksl_physical_parameters.py`, `gksl_validation.py`: 変更不要
- `stinespring_utils.py`: 汎用実装のため変更不要

## 期待される結果

修正後:

1. **ノイズなし (qubit vs qudit)**: 結果はほぼ同一（浮動小数点誤差の範囲）
   - これは物理的に正しい：同一のTrotter分解を使用する限り、符号化方式は結果に影響しない
   - 違いは計算コスト（256次元 vs 81次元）と禁止状態リーケージ（~0）のみ

2. **ノイズあり (qubit_noisy vs qudit_noisy)**: 結果が有意に異なる
   - 量子ビット: d=4パウリノイズ + リーケージ → より大きな情報損失
   - キュートリット: d=3 Weyl-Heisenbergノイズ → リーケージなし
   - F(qubit_noisy, qudit_noisy) < 現在の0.9547（ノイズモデルの違いが拡大）

3. **量子ビットの禁止状態リーケージ**: ノイズシナリオで定量的に報告
   - p_depol=0.01での1ステップあたりリーケージ確率を定量化
   - これが量子ディットの優位性の定量的根拠となる
