## 発見された問題点

### 問題1（重要）: 密度行列シミュレータにおけるStinespring/Hamiltonian expmの冗長再計算

**対象ファイル:**
- `qubit_gksl_simulator.py` (QubitGKSLSimulator)
- `qudit_gksl_simulator.py` (QuditGKSLSimulator)
- `qubit_gksl_boson_simulator.py` (QubitGKSLBosonSimulator)
- `qudit_gksl_boson_simulator.py` (QuditGKSLBosonSimulator)

**現象:**

`_trotter_step` メソッドが呼び出されるたびに、以下が再計算されている:

1. `expm(-1j * self.H_total * dt / 2)` — ハミルトニアン指数関数（各ステップで2回）
2. `stinespring_unitary_from_lindblad(L_op, dt)` — 各リンドブラッドチャネルのStinespringユニタリ（各ステップで26回）

`dt` は全ステップで一定であるため、これらは1回だけ計算すればよい。

**影響:**

- QubitGKSLSimulator: n_steps=5で、512×512行列のexpmが130回呼ばれる（本来は26回）、256×256のexpmが10回（本来は1回）
- QuditGKSLSimulator: 162×162行列のexpmが130回（本来は26回）、81×81のexpmが10回（本来は1回）
- 計算時間の約80%が冗長計算

**参考:** shot系シミュレータ（QubitGKSLShotSimulator, QuditGKSLShotSimulator）は既に
`_precompute_unitaries()` メソッドで事前計算を実装済み。密度行列シミュレータにも
同様の事前計算を適用すべき。

**修正方針:** `simulate()` メソッド内で `_precompute_unitaries(dt)` を呼び出し、
キャッシュされたユニタリを `_trotter_step` で使用する。

**深刻度: 重要**（正確性には影響しないが、計算効率に大きく影響）

### 問題2（中程度）: QubitGKSLNoisyShotSimulatorにディフェージングチャネルがない

**現象:**

| ノイズ種別 | QuditGKSLNoisyShotSimulator | QubitGKSLNoisyShotSimulator |
|-----------|---------------------------|---------------------------|
| 脱分極 | ✅ p_depol（d=3 Weyl-Heisenberg） | ✅ p_depol（d=4 パウリ） |
| ディフェージング | ✅ p_dephasing | ❌ なし |
| 熱緩和 | ❌ なし | ✅ T1, t_gate |

**問題点:**

1. **APIの非対称性**: quditノイズシミュレータはディフェージングをサポートするが、
   qubitノイズシミュレータはサポートしない。
2. **公平な比較の不可能性**: ノイズ種別が異なるため、符号化方式の違い（qubit vs qudit）の
   効果を、ノイズモデルの違いの効果から分離できない。
3. **検証スクリプトの問題**: `run_tta_uc_gksl_verification.py` がquditには(p_depol=0.01,
   p_dephasing=0.005)、qubitには(p_depol=0.01, T1=50000, t_gate=300)と異なるノイズを使用。

**修正方針:**

1. `QubitGKSLNoisyShotSimulator` に `p_dephasing` パラメータを追加
2. qubit空間でのディフェージングノイズを実装（Z-typeパウリ投影）
3. 検証スクリプトに同一ノイズパラメータでの比較シナリオを追加

**深刻度: 中程度**（物理モデルの完全性）

---

### 問題3（軽微）: リーケージシナリオのトレース誤差報告が不正確

**現象:**

qubit_noisy_shot の検証結果:
- `final_trace: 0.672713441501`（禁止状態へのリーケージにより1未満）
- `max_trace_error: 0.000e+00`（0と報告！）

**根本原因:**

`_validate_result` の `allow_leakage=True` 時のロジック:
```python
if allow_leakage:
    if tv > 1.0 + 1e-8:
        max_trace_error = max(max_trace_error, tv - 1.0)
```

trace < 1（リーケージによる物理的に期待される減少）は記録されず、
trace > 1（非物理的な増加）のみを検査する。
結果として `max_trace_error = 0` となるが、これはトレースが完全に保存されているかのように
誤解される。

**修正方針:**

リーケージシナリオ用に `max_trace_deficit`（1 - trace の最大値）メトリクスを追加。
これにより禁止状態リーケージの程度が明確に報告される。

**深刻度: 軽微**（報告の明確性）

---

### 問題4（軽微）: 検証スクリプトのノイズ比較が非対称

**現象:**

現在の検証スクリプトでは:
- qudit_noisy_shot: 脱分極 (p=0.01) + ディフェージング (p=0.005)
- qubit_noisy_shot: 脱分極 (p=0.01) + 熱緩和 (T1=50000, t_gate=300)

異なるノイズ種別を使用しているため、結果の差異が符号化方式によるものか
ノイズモデルの違いによるものか区別できない。

**修正方針:**

1. 同一ノイズパラメータ（脱分極のみ）での比較シナリオを追加
2. 符号化方式の違いのみに起因するリーケージ効果を定量化

**深刻度: 軽微**（テスト設計）

- **Stinespring dilation理論**: 正確に実装されている（1次近似: E(ρ) ≈ ρ + dt(LρL† − ½{L†L,ρ})）

- **パウリノイズモデル**: d=4局所空間での正しい脱分極チャネル
- **熱緩和モデル**: 2量子ビットKraus分解が正しく実装
- **禁止状態リーケージ追跡**: 正しく実装・報告
