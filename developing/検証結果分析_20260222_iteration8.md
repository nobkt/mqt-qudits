## 発見された問題点

### 問題1（中程度）: ボソンシミュレータ間のトレース時系列の不整合

**対象ファイル:**
- `tutorials/qudit_gksl_boson_simulator.py`（行158, 166）
- `tutorials/qubit_gksl_boson_simulator.py`（行252, 260）
- `tutorials/classical_gksl_boson_simulator.py`（行160）— 基準（正しい）

**現象:**

3つのボソンシミュレータは、電子自由度の縮約密度行列 ρ_el からエントロピー・純度・
人口数を計算しているが、トレース時系列だけが不整合である:

| シミュレータ | trace報告対象 | コード |
|-------------|-------------|--------|
| classical_gksl_boson | Tr(ρ_el) | `np.trace(rho_el)` |
| qudit_gksl_boson | Tr(ρ_total) | `np.trace(rho)` — **不整合** |
| qubit_gksl_boson | Tr(ρ_total) | `np.trace(rho)` — **不整合** |

**問題点:**

1. **物理量の意味の不一致**: `trace`時系列は検証スクリプト（`_validate_result`）で
   `|trace - 1| < tolerance` の検証に使用される。ρ_totalとρ_elは部分トレースの
   性質により `Tr(ρ_total) = Tr(ρ_el)` が数学的に成立するが、浮動小数点精度が
   異なるため、同一の物理量を異なる精度で報告することになる。

2. **一貫性の欠如**: 同一の検証パイプラインで、他の全オブザーバブル（entropy, 
   purity, populations）は ρ_el から計算されているのに、traceだけが ρ_total から
   計算されている。これはシミュレータ間の比較時に混乱を招く。

**実測値の差異:**

| シミュレータ | 最終trace値 | 出処 |
|-------------|------------|------|
| classical_boson | 1.0000000000000004 | Tr(ρ_el) |
| qudit_boson | 1.0000000000000009 | Tr(ρ_total) |
| qubit_boson | 1.0000000000000009 | Tr(ρ_total) |

部分トレースの追加的浮動小数点丸めにより、Tr(ρ_el)の方がTr(ρ_total)に比べて
若干異なる精度特性を持つ。

**修正方針:**

qudit/qubit ボソンシミュレータのtrace記録を、他のオブザーバブルと同じく
ρ_el から計算するように修正:

```python
# 変更前:
traces.append(float(np.real(np.trace(rho))))      # ρ_total
# 変更後:
traces.append(float(np.real(np.trace(rho_el))))    # ρ_el
```

**深刻度: 中程度**（シミュレータ間の一貫性）

### 問題2（軽微）: quantum_fidelity の浮動小数点オーバーフロー

**対象ファイル:** `tutorials/run_tta_uc_gksl_verification.py`（quantum_fidelity関数）

**現象:**

Uhlmann忠実度 F(ρ,σ) = (Tr√(√ρ·σ·√ρ))² は理論的に [0, 1] の範囲に制限されるが、
浮動小数点演算の誤差により 1.0 を超える値が返される場合がある:

```json
{
    "scenario_a": "qubit",
    "scenario_b": "qudit",
    "fidelity": 1.0000002199321472
}
```

**問題点:**

1. **理論的不正確**: F > 1 は物理的に不可能な値であり、これが検証レポートに
   記載されると、結果の信頼性を損なう。

2. **下流への影響**: fidelityの値が [0, 1] の範囲外であることを前提としない
   コードが将来的に追加された場合、予期しない動作を引き起こす可能性がある
   （例: arccos(F) の計算でBuresメトリクスを求める場合など）。

**修正方針:**

理論的に保証される [0, 1] への制限（クランプ）を適用する。これはごまかしの
heuristicではなく、理論が保証する上界 F ≤ 1 の数値的実現である:

```python
return float(min(np.real(np.sum(np.sqrt(evals_m))) ** 2, 1.0))
```

**深刻度: 軽微**（浮動小数点の数値的整合性）

## qubit_noisy_shot の物理的分析（再確認）

qubit_noisy_shot の 34.4% トレース欠損はコードバグではなく、
qubit符号化（|00⟩=S0, |01⟩=T1, |10⟩=S1, |11⟩=禁止）の物理的性質である。

15個の非恒等2-qubitパウリ中、12個がリーケージを引き起こし得る:
- |00⟩→|11⟩: XX, XY, YX, YY（4個）
- |01⟩→|11⟩: XI, XZ, YI, YZ（4個）
- |10⟩→|11⟩: IX, IY, ZX, ZY（4個）
- リーケージなし: IZ, ZI, ZZ（3個のみ）

12/15 = 80% の非恒等パウリがリーケージ可能であり、
380回のノイズ操作で累積的にリーケージが蓄積する。
これはqubit量子コンピュータでこのTTA-UCモデルを実行した場合の
実際の計算精度を正しく反映している。
