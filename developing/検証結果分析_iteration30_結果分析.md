## 2. コード正当性分析

### 2.1 Stinespring dilation 実装の数学的検証

`stinespring_utils.py` の実装：

```
G = [[0, L†], [L, 0]]
θ = √dt
U = expm(-iθG)
```

Taylor 展開による検証：
- K₀ = ⟨0|U|0⟩ ≈ I - (dt/2)L†L + O(dt²)
- K₁ = ⟨1|U|0⟩ ≈ -i√dt · L + O(dt^{3/2})
- E(ρ) = K₀ρK₀† + K₁ρK₁† ≈ ρ + dt(LρL† - ½{L†L, ρ}) + O(dt²)

これは GKSL 散逸子の 1 次近似を正確に再現する。**実装に誤りはない。**

### 2.2 Trotter 分割の検証

`qudit_gksl_simulator.py` の対称 Trotter ステップ：

```
exp(L_H dt/2) · ∏_{α=1..n} E_α(dt/2) · ∏_{α=n..1} E_α(dt/2) · exp(L_H dt/2)
```

- Strang H-D 分割: O(dt³)/step → O(dt²) global ✓
- 回文順 Lindblad 積: Lie-Trotter 交換子誤差の 2 次消去 ✓
- Stinespring 近似: O(dt²)/step → **O(dt) global** ← これが支配的

### 2.3 SCPT 参照実装の検証

`_symmetric_classical_product_trotter_simulate` は ST と同一の回文順序を使用するが、
Stinespring の代わりに厳密なチャネル指数関数を使用：

```
exp(L_H dt/2) · ∏_{α=1..n} exp(L_{D_α} dt/2) · ∏_{α=n..1} exp(L_{D_α} dt/2) · exp(L_H dt/2)
```

ST vs SCPT は純粋な Stinespring 近似誤差を分離する。Rate(T) = 1.00 ± 0.01 が全 dt で
確認されており、Stinespring 誤差が O(dt) であることを直接実証している。

### 2.4 結論: コードにバグは存在しない

O(dt) 収束は **バグではなく、Stinespring dilation の理論的に正しい振る舞い** である。

### 3.2 問題の本質

**Iteration 24〜30 の 7 回分は、シミュレーターの「誤差の記述モデル」を精緻化する作業であり、
シミュレーター自体の精度を改善する作業ではない。**

具体的に：
- M1〜M7 は観測された誤差を dt の多項式関数で近似するパラメトリックモデル
- これらのモデルは「誤差がどう振る舞うか」を記述するだけであり、誤差を削減しない
- シミュレーターのコードはイテレーション 22 以降、本質的に変更されていない
- 各イテレーションでの「修正」は検証スクリプト内のフィッティングコードの改良のみ

### 3.3 誤認の構造

```
正しい理解:
  シミュレーター → O(dt) 誤差（正しい振る舞い）
  M7 モデル → 0.011% の精度で誤差を記述（優秀なモデル）
  
誤認:
  M7 モデル誤差 0.011% ≈ シミュレーター誤差 0.011%  ← これは間違い
  
実際:
  M7 モデル誤差 0.011% = 「誤差の記述」の精度
  シミュレーター誤差 = T(ST, exact) ≈ a·dt（dt に比例、モデルとは無関係）
```

### 3.4 O(dt) 収束は「修正すべき問題」か？

**No.** O(dt) 収束は Stinespring dilation の数学的性質であり、バグではない。

Stinespring dilation は量子回路で実装可能な GKSL チャネルの近似方法として設計されており、
O(dt) の精度は量子コンピュータ上での実用的なシミュレーションには十分である。
理由：量子ノイズ（p_depol）が Trotter 誤差を 1000 倍以上上回る（Test A で確認済み）。
