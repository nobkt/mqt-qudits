# TTA-UC GKSL 検証ループ根本原因分析

## 分析日時: 2026-03-04

## 1. 結論（先に述べる）

### 1.1 GKSLシミュレータコードに数学的・物理的バグは存在しない

イテレーション11～45にわたる34項目の検証チェックは、**全て一貫してPASS**しています。
具体的に検証済みの項目：

- Stinespring dilation: CPTP チャネル、O(dt²) 誤差 ✓
- GKSL superoperator: トレース保存（6.94e-18 精度）、全固有値 Re(λ)≤0 ✓
- Lindblad 演算子: 正しいTTAチャネル構造、√γ 因子の包含 ✓
- Trotter 分解: Strang対称分割 + 回文順序 ✓
- Qubit-Qutrit マッピング: 物理部分空間の同値性 ✓
- Shot-based シミュレータ: Born 則測定、量子軌道の正確性 ✓
- Boson シミュレータ: Holstein結合、拡張空間構造 ✓
- 収束次数: O(Δt) 全体収束（Stinespring dilation の数学的性質） ✓
- 粒子数保存: 古典 2.2e-14、Qudit 8.2e-14 ✓

### 1.2 修正が終わらない根本原因は「自己参照的無限ループ」

**コードのバグではなく、検証プロセス自体のバグです。**

## 2. 根本原因の詳細分析

### 2.1 自己参照的イテレーションカウンタ

ノートブック `quantum_dynamics_gksl_comparison.ipynb` のセル25とセル39に、以下の文言が含まれています：

- セル25: `"44回のイテレーション検証により確認された収束特性を定量的に示します。"`
- セル39: `"### 収束特性（44回の検証イテレーションで確認済み）"`

各イテレーションの検証スクリプトは、このカウンタが正しく更新されているかをチェックします（check 7, 8, 31）。

### 2.2 無限ループのメカニズム

```
イテレーション N の検証スクリプト:
  → ノートブックに "(N-1)回" があることを確認 → PASS
  → 結果: "問題なし。次のイテレーションでは N回 に更新する必要がある"

イテレーション N+1 の検証スクリプト:
  → ノートブックに "N回" があることを確認 → PASS  
  → 結果: "問題なし。次のイテレーションでは (N+1)回 に更新する必要がある"

イテレーション N+2 の検証スクリプト:
  → ノートブックに "(N+1)回" があることを確認 → PASS
  → 結果: ...（永遠に続く）
```

**これは停止しないプロセスです。** 検証行為自体が「検証されるべき変更」を生成するため、不動点が存在しません。

4. 作業ログを作成

### 2.4 チェック7, 8, 31の問題

これらのチェックは「ドキュメントの内容が正しいか」ではなく、「ドキュメントが最後のイテレーションで更新されたか」を検証しています。これは：

- **コードの正確性とは無関係**
- **自己参照的**（チェック自体がチェック対象を変更する必要を生成する）
- **収束しない**（不動点が存在しない）

## 3. 修正方針

### 3.1 ノートブックの修正

セル25とセル39のイテレーションカウンタを、**具体的な数値から汎用的な記述に変更**します。

- Before: `"44回のイテレーション検証により確認された"`
- After: `"複数回のイテレーション検証により確認された"`

これにより、ノートブックの内容は検証回数に依存しなくなり、自己参照ループが断ち切られます。

### 3.2 検証スクリプトの修正

- check 7, 8, 31（イテレーションカウンタの検証）を **削除**
- ドキュメント内容の整合性チェック（cell 27 の数値テーブル）は **保持**
- 安定した、イテレーション番号に依存しない検証スクリプトを作成

### 3.3 不要なファイルの削除は行わない

過去のイテレーション固有のスクリプト（`run_tta_uc_gksl_verification_iteration11.py` 等）は、
履歴として残します。削除はプロジェクトオーナーの判断に委ねます。

## 4. 数学的正確性の最終確認

### 4.1 収束次数 O(Δt) は正しい

Stinespring dilation の近似：

$$\mathcal{E}_\alpha(\rho) = \rho + \Delta t \left(L_\alpha \rho L_\alpha^\dagger - \frac{1}{2}\{L_\alpha^\dagger L_\alpha, \rho\}\right) + O(\Delta t^2)$$

各ステップで O(Δt²) の誤差があり、T/Δt ステップで合計すると O(Δt) の全体誤差。
これは数学的に正しく、バグではありません。

### 4.2 検証数値の確認

|---------|-----|---------------|----------|------|
| 10 | 10.0 | 0.01294 | 0.999666 | - |

| 200 | 0.5 | 0.00036 | 1.000000 | 1.013 |

収束レート → 1.0 は O(Δt) 収束を確認。全て正常。

## 5. 今後の推奨事項

1. **自己参照的チェックの完全な除去**: イテレーション番号に依存するチェックは設計として不適切
2. **安定した回帰テスト**: `run_tta_uc_gksl_verification.py`（イテレーション番号なし）を作成
3. **検証プロセスの終了条件の明確化**: 「全チェックPASS」を終了条件とし、ドキュメントの内容は検証対象外とする
4. **CI統合**: 安定した検証スクリプトをCIパイプラインに組み込み、自動検証を行う
