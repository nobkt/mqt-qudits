## 発見された問題点

### 問題1（重要）: validate_density_matrix のトレース許容値ハック

**対象ファイル:**
- `tutorials/gksl_validation.py` (validate_density_matrix)
- `tutorials/run_tta_uc_gksl_verification.py` (_validate_result)

**現象:**

qubit_noisy_shot シナリオでは、禁止状態(|11⟩)へのリーケージにより
qutrit空間の密度行列のトレースが 1 未満になる（検証結果: trace=0.656）。

現在のコードは、これを以下のように処理している:

```python
# run_tta_uc_gksl_verification.py, line 146
dm_tolerance = {"trace": 0.5} if allow_leakage else None
density_validation = validate_density_matrix(
    result["rho_final"], step=n_steps, tolerance=dm_tolerance
)
```

validate_density_matrix のデフォルトトレース許容値（1e-8）を
0.5 に引き上げることで、|trace - 1.0| = 0.344 < 0.5 を通過させている。

**問題点:**

1. **任意の閾値**: 0.5は物理的根拠のない任意の値。リーケージが50%を超えた場合に
   初めてエラーとなるが、50%という閾値に理論的意味はない。

2. **ごまかしのheuristic**: 問題の本質は「サブノーマライズされた密度行列を
   ノーマライズされた密度行列と同じ検証関数で扱っている」ことであり、
   許容値の引き上げはこの構造的問題の回避策である。

3. **物理的に不正確**: validate_density_matrix は `|trace - 1| < tolerance`
   を検証するが、サブノーマライズ密度行列に対する正しい検証は
   `0 ≤ trace ≤ 1 + ε` である。

**修正方針:**

validate_density_matrix に `allow_subnormalized` パラメータを追加し、
サブノーマライズ密度行列に対する適切な検証を行う:

- `allow_subnormalized=False`（デフォルト）: 従来通り |trace - 1| < ε を検証
- `allow_subnormalized=True`: 0 ≤ trace ≤ 1 + ε を検証（trace < 1 は許容）

**深刻度: 重要**（ごまかしのheuristicの除去）

### 問題2（中程度）: サブノーマライズ密度行列からのエントロピー・純度の比較不可能性

**対象ファイル:** `tutorials/run_tta_uc_gksl_verification.py`

**現象:**

qubit_noisy_shot の密度行列はサブノーマライズ（trace < 1）であるため、
エントロピーと純度がノーマライズ状態と直接比較できない:

| メトリクス | qudit_noisy_shot (trace=1.0) | qubit_noisy_shot (trace=0.656) | 比較可能性 |
|-----------|------------------------------|-------------------------------|-----------|
| S(ρ) | 3.242 | 2.130 | ❌ 不可 |
| Tr(ρ²) | 0.103 | 0.074 | ❌ 不可 |
| S(ρ/tr) | 3.242 | ≈3.67 | ✅ 可能 |
| Tr((ρ/tr)²) | 0.103 | ≈0.172 | ✅ 可能 |

サブノーマライズ密度行列の S(ρ) = -Σ λ_i ln λ_i は、Σ λ_i = tr < 1 であるため、
ノーマライズ状態の von Neumann エントロピーとは異なる量である。

**修正方針:**

qubit_noisy_shot（allow_leakage=True）のシナリオに対して、
検証レポートにノーマライズされたエントロピーと純度を追加する:

```python
S_normalized = (S_raw + trace * np.log(trace)) / trace  # if trace > 0
P_normalized = P_raw / (trace ** 2)
```

これにより、物理的部分空間に制限された状態のエントロピー/純度を
他のシナリオと公平に比較できる。

**深刻度: 中程度**（検証レポートの定量的比較能力）

## qubit_noisy_shot の物理的分析

### リーケージの原因と定量的解析

qubit_noisy_shot の 34.4% トレース欠損はコードバグではなく、
qubit符号化（|00⟩=S0, |01⟩=T1, |10⟩=S1, |11⟩=禁止）の物理的性質である。

**1ステップあたりのノイズ操作回数:**

| ゲート種別 | 回数 | ノイズ操作/回 | 合計 |
|-----------|------|-------------|------|
| ハミルトニアン転送（×2） | 3対×2 | 1 pair depol + 2 single dephasing | 18 |
| Lindbladペアチャネル | 6 | 1 pair depol + 2 single dephasing | 18 |
| Lindblad単サイトチャネル | 20 | 1 single depol + 1 single dephasing | 40 |
| **合計** | | | **76** |

5ステップで合計380回のノイズ操作。

**qubit符号化固有のリーケージメカニズム:**

単サイト脱分極（d=4）で物理状態 |ψ⟩ ∈ {|00⟩, |01⟩, |10⟩} に
非恒等パウリ誤りが発生した場合:
- 15個の非恒等パウリ中4個が |11⟩ へのリーケージを発生
- 1回の脱分極操作あたりのリーケージ確率 ≈ p × (4/15) × (15/16) ≈ p/4

p_depol=0.01 で1回あたり ~0.25% のリーケージ。
380回のノイズ操作で累積的にリーケージが蓄積し、最終的に34%に達する。

**これはqubit量子コンピュータでこのTTA-UCモデルを実行した場合の
実際の計算精度を正しく反映している。**

### qubit vs qudit のノイズモデル差異

| パラメータ | qudit (d=3) | qubit (d=4) |
|-----------|-------------|-------------|
| 単サイト depol: E(ρ) = (1-p)ρ + (p/d)I | p/3 identity mixing | p/4 identity mixing |
| ペア depol: E(ρ) = (1-p)ρ + (p/d²)I | p/9 identity mixing | p/16 identity mixing |
| 禁止状態リーケージ | なし（全状態物理的） | あり（|11⟩へのリーケージ） |
| 実効ノイズ強度（物理部分空間） | 脱分極のみ | 脱分極 + リーケージ |

同じ p_depol=0.01 でも、qubit符号化はリーケージにより実質的に
はるかに強いノイズを受ける。fidelity(qudit_noisy, qubit_noisy) = 0.938 は
この符号化方式差を正しく反映している。
