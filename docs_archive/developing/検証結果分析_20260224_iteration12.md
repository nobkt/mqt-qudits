## 3. 各問題の詳細分析

### 問題1: ノイズチャネルの確率的実装の独立検証がない

**現状**: ショットベースシミュレータ（`QuditGKSLNoisyShotSimulator`, `QubitGKSLNoisyShotSimulator`）は
量子軌道法（確率的ノイズ適用）を使用している。この確率的実装が密度行列レベルのチャネルと
正確に一致することの独立検証が存在しない。

**なぜ重要か**: ノイズモデルの正当性は、Kraus分解の確率的unravelingが
密度行列チャネルの平均に一致することに依存する。実装ミスがあれば
全てのノイズ付きシミュレーション結果が無意味になる。

**検証方法**: 少数ステップ（1〜2ステップ）で以下を比較する：
1. 密度行列レベルでノイズチャネルを解析的に適用した結果
2. 大量ショット（10000+）での確率的平均結果
3. 両者の忠実度が1に近いことを確認

### 問題2: Cell 29のトレース出力欠落

**現状**: Cell 29（Qudit noisy shot）は以下を出力している：
```
Elapsed time: 58.80s
Noise: p_depol=0.01, p_dephasing=0.005
Final populations: N_S0=1.6389, N_T1=1.1859, N_S1=1.1752
```

しかし他の全セル（Cell 4, 6, 8, 10, 12, 14, 27, 31）では
`Trace conservation: max|Tr-1| = ...` を出力しているのに対し、Cell 29ではこの出力がない。

**影響**: Qudit noisy simulatorがTr(ρ)=1を保存しているかの確認が
ノートブック出力からは直接確認できない（Cell 35の出力で間接的に確認可能だが不十分）。

**修正**: Cell 29にトレース保存チェック出力を追加する。

### 問題3: qubit_noisy vs qudit_noisy の正規化忠実度比較の欠落

**現状**: Cell 35は以下のペアの忠実度を計算している：
- Qudit DM vs Qudit Shot (no noise)
- Qubit DM vs Qubit Shot (no noise)
- Qudit DM vs Qudit Noisy (raw/norm)
- Qubit DM vs Qubit Noisy (raw/norm)

しかし**qubit_noisy vs qudit_noisy の直接比較**が欠落している。

**なぜ重要か**: iteration 11の検証（5ステップ）では qubit_noisy vs qudit_noisy の
正規化忠実度 F_norm = 0.938 と高い値が得られた。これは物理部分空間内でのノイズ影響が
qubit/quditで類似していることを示す重要な知見だが、100ステップでの値は未検証。

**修正**: Cell 35に qubit_noisy vs qudit_noisy の忠実度比較を追加する。

### 問題4: 定量的エラーバジェット分析の欠落

**現状**: Cell 34のマークダウンはqubit/quditノイズの質的な違いを説明しているが、
定量的なエラーバジェット（1ステップあたりのノイズゲート数、累積エラー率）の分析がない。

**分析結果**:

#### Qudit noisy simulator（1トロッターステップあたりのノイズ適用回数）

| フェーズ | 操作 | 脱分極 | 位相緩和 | 小計 |
|---------|------|--------|---------|------|
| Hamiltonian前半 | 3ペア転送ゲート | 3回(pair) | 6回(single) | 9回 |
| Lindblad (pair) | 6チャネル | 6回(pair) | 12回(single) | 18回 |
| Lindblad (single) | 20チャネル | 20回(single) | 20回(single) | 40回 |
| Hamiltonian後半 | 3ペア転送ゲート | 3回(pair) | 6回(single) | 9回 |
| **合計** | | **32回** | **44回** | **76回** |

注: VirtRz（H_0対角ゲート4個）にはノイズ適用なし。これは単一quditゲートが
一般に2-quditゲートより低いエラー率を持つためのモデリング選択。

#### 100ステップ累積ノイズ推定

- 総ノイズ適用回数: 76 × 100 = 7,600回
- 脱分極エラー期待回数: 32 × 0.01 × 100 = 32回（pair） + 20 × 0.01 × 100 = 20回（single）
- 位相緩和イベント期待回数: 44 × 0.005 × 100 = 22回

これは**極めて大量のノイズ**であり、量子状態がほぼ完全に最大混合状態に近づくことを意味する。
実際の出力（N_S0≈1.64, N_T1≈1.19, N_S1≈1.18、合計=4.0）は最大混合状態（各≈1.33）に近い。

### 問題5: ステップ毎の忠実度劣化追跡の欠如

**現状**: Cell 35は最終状態の忠実度のみを表示。ノイズが時間とともに
どう蓄積するかの情報がない。

**なぜ重要か**: ノイズモデルの正しさを検証するには、ステップごとの
忠実度劣化曲線が指数的減衰 F(n) ∝ (1-ε)^n に従うかを確認する必要がある。
異常な振る舞い（非単調減少、急激なジャンプ等）があればバグの可能性を示唆する。

**検証方法**: 検証スクリプトで少数ステップ（5〜20ステップ）のシミュレーションを実行し、
各ステップでの参照状態との忠実度を計算・出力する。

### 問題6: ノイズ蓄積の理論値 vs 観測値の比較

**現状**: ノイズモデルが正しく実装されているなら、密度行列レベルでの
脱分極チャネルの累積効果を解析的に計算できる。この理論値と
ショットベースシミュレーションの観測値の比較がない。

**理論的背景**: 単一サイト脱分極チャネル E(ρ) = (1-p)ρ + (p/d)I·Tr(ρ) の
n回適用後の忠実度は解析的に計算可能。ただし、Trotter分解の
Hamiltonian発展と組み合わさるため、厳密な解析解は得られない。
そのため、密度行列レベルでノイズチャネルを直接適用した数値結果との比較が必要。

## 4. コードの数学的正当性確認

以下のコンポーネントについて数学的正当性を確認した：

### 4.1 Stinespring dilation（stinespring_utils.py）
- G = [[0, L†], [L, 0]], U = exp(-i√dt · G) ✓
- 部分トレースの実装: rho_out = ρ'[:d,:d] + ρ'[d:,d:] ✓
- テンソル積順序: |anc⟩⊗|sys⟩ で一貫 ✓

### 4.2 Weyl-Heisenberg脱分極（qudit_gksl_shot_simulator.py）
- 確率分配: p_identity = 1-p+p/d², p_error = p/d² × (d²-1) ✓
- チャネル: E(ρ) = (1-p)ρ + (p/d)I·Tr(ρ) ✓
- ペア脱分極: d⁴-1個の非恒等演算子に均等確率 ✓

### 4.3 Qubit Pauli脱分極（qubit_gksl_shot_simulator.py）
- 2-qubit Pauli（4×4行列）16個の構成 ✓
- ペア脱分極: 4-qubit Pauli（256個）の分解 ✓
- 禁止状態リーケージ: 15個中12個（80%）の非恒等Pauliがリーケージ発生 ✓（物理的に正しい）

### 4.4 量子忠実度（Cell 24）
- F(ρ,σ) = (Tr√(√ρ·σ·√ρ))² の固有値分解実装 ✓
- サブノーマライズ行列への適用: F_raw = Tr(σ) · F_norm の関係 ✓

### 4.5 抽出・埋め込み（qubit_gksl_simulator.py）
- qutrit↔qubit空間のマッピング ✓
- extract_statevector_from_qubit_space はサブノーマライズを保持（正しい） ✓

## 6. 結論

コード自体に致命的なバグは発見されなかった。Stinespring dilation、ノイズモデル、
量子忠実度計算の全てが数学的に正当である。

主な問題は**診断出力の不足**と**独立検証の欠如**であり、
ノイズモデルの正しさを数値的に確認するための検証スクリプトと、
ノートブックへの追加診断出力が必要である。

特に、確率的ノイズ実装が密度行列チャネルと一致することの
数値的検証は、全てのノイズ付きシミュレーション結果の信頼性を
担保するために不可欠である。
