## 1. 発見されたバグの一覧

### バグ1（致命的）: `QuditGKSLNoisySimulator._trotter_step` が完全に壊れている

**ファイル**: `tutorials/qudit_gksl_noisy_simulator.py`

**症状**: `QuditGKSLNoisySimulator.simulate()` を呼び出すと `TypeError` で即座にクラッシュする。

**原因**: 3つの独立した問題が存在する:

1. **シグネチャ不一致**: `_trotter_step(self, rho, dt)` はパラメータ `dt` を追加しているが、親クラス `QuditGKSLSimulator.simulate()` は `self._trotter_step(rho)` と1引数で呼び出す。`TypeError: _trotter_step() missing 1 required positional argument: 'dt'` が発生する。

2. **未定義メソッド `_apply_hamiltonian_step`**: `self._apply_hamiltonian_step(rho, dt / 2)` を呼び出しているが、このメソッドは `QuditGKSLSimulator` にも `QuditGKSLNoisySimulator` にも定義されていない。`qudit_gksl_circuit_boson_simulator.py` には存在するが、継承関係にない。

3. **未定義メソッド `_apply_lindblad_stinespring`**: `self._apply_lindblad_stinespring(rho, L_op, dt)` を呼び出しているが、このメソッドはどこにも定義されていない。

**実証**:
```python
sim = QuditGKSLNoisySimulator(params, p_depol=0.01, p_dephasing=0.005)
sim.simulate(t_max=1.0, n_steps=1, initial_state='edge_triplet')
# → TypeError: QuditGKSLNoisySimulator._trotter_step() missing 1 required positional argument: 'dt'
```

### バグ2（致命的）: `QubitGKSLNoisySimulator._trotter_step` が完全に壊れている

**ファイル**: `tutorials/qubit_gksl_noisy_simulator.py`

**症状・原因**: バグ1と全く同じ3つの問題。

1. `_trotter_step(self, rho, dt)` のシグネチャ不一致
2. `self._apply_hamiltonian_step(rho, dt / 2)` が未定義
3. `self._apply_lindblad_stinespring(rho, L_op, dt)` が未定義

**実証**:

```python
sim = QubitGKSLNoisySimulator(params, p_depol=0.01)
sim.simulate(t_max=1.0, n_steps=1, initial_state='edge_triplet')

```

### バグ3（設計不整合）: DM noisy vs shot noisy のノイズ適用パターンの差異

**ファイル**: `qudit_gksl_noisy_simulator.py` vs `qudit_gksl_shot_simulator.py`

**問題**: 密度行列ノイジーシミュレータ (`QuditGKSLNoisySimulator`) はHamiltonian半ステップ後にペア脱分極のみを適用する。一方、ショットベースノイジーシミュレータ (`QuditGKSLNoisyShotSimulator`) はペア脱分極 + ディフェージングを適用する。

DM noisy (壊れているが、コードを読むと):
```python
# --- Half Hamiltonian ---
rho = self._apply_hamiltonian_step(rho, dt / 2)
for i, j in self.params.neighbors:
    rho = _apply_local_depolarization_pair(rho, i, j, d, N, self.p_depol)
# → ディフェージング無し!
```

Shot noisy:
```python
psi = self._U_H_half @ psi
for i, j in self.params.neighbors:
    psi = _apply_stochastic_depolarization_pair(psi, i, j, d, N, self.p_depol, rng)
    if self.p_dephasing > 0.0:
        psi = _apply_stochastic_dephasing_single(psi, i, d, N, self.p_dephasing, rng)
        psi = _apply_stochastic_dephasing_single(psi, j, d, N, self.p_dephasing, rng)
```

同じノイズモデルを名乗りながら、ノイズの適用パターンが異なるため、修正時にショットベースの実装と一致させる必要がある。

### バグ4（検証スクリプトの不正確さ）: test_noise_channel_verification の解析的パスの不整合

**ファイル**: `tutorials/run_tta_uc_gksl_verification_iteration12.py`

**問題**: `test_noise_channel_verification()` 関数の解析的パスは、まずノイズレスのTrotterステップ全体を実行し、その後にノイズチャネルを順番に適用している。しかし、確率的シミュレータはTrotterステップ内でゲートとノイズを交互に適用する。

解析的パス:
```
1. U_H_half @ rho @ U_H_half†  (半Hamiltonian)
2. 全Stinespring適用 (ノイズレス)
3. U_H_half @ rho @ U_H_half†  (半Hamiltonian)
4. [ノイズチャネル適用: Phase 1, 2, 3 全部まとめて]
```

確率的パス (QuditGKSLNoisyShotSimulator):
```
1. U_H_half @ psi          → ノイズ(Phase 1)
2. 各Stinespring + 測定   → 各チャネル後にノイズ(Phase 2)
3. U_H_half @ psi          → ノイズ(Phase 3)
```

ノイズの配置が異なるため、数学的に等価ではない。1ステップ・小ノイズの場合は近似的に一致する（F≈0.996）が、厳密な検証にはなっていない。

## 2. iteration12検証データの分析

### 2.1 Test 1結果の再解釈

- F(解析的, 確率的) = 0.996183 → **ノイズ配置の差異にもかかわらず高い忠実度**
- しかしこれはバグ4により、真の「解析的チャネルと確率的実装の一致」を検証していない

### 2.2 Test 2結果の再解釈

- **Quditノイジーのトレース = 1.0 (全ステップ)**: 正しい。Qutrit空間にforbidden stateがないため。
- **Qubitノイジーのトレース減衰 (1.0 → 0.532)**: これは**物理的に正しい**挙動。Qubit encoding + Pauliノイズにより|11> forbidden stateにリークする。Qutrit空間への射影でトレースが減少する。
- **F(qudit_dm, qudit_noisy) = 0.0897**: エラーバジェット分析と整合。76ノイズゲート/ステップ × 10ステップ = 760ノイズ適用で、生存確率は exp(-6.76) ≈ 0.001 のオーダー。ショットノイズの影響も加わりF≈0.09は妥当。
- **F(qudit_noisy, qubit_noisy) norm = 0.929**: トレース正規化後のcross-fidelityが高いことは、両シミュレータがノイズの影響下で類似したダイナミクスを再現していることを示す。

### 2.3 Test 3: エラーバジェット

エラーバジェットの計算は正確。76ノイズゲート/ステップという数値は、シミュレータのTrotterステップ構造と一致している。

## 4. 修正方針

### 4.1 DM noisyシミュレータの修正

`QuditGKSLNoisySimulator` と `QubitGKSLNoisySimulator` の `_trotter_step` を修正する:

1. `_trotter_step` のシグネチャを親クラスと一致させる (`dt` パラメータを削除)
2. `_apply_hamiltonian_step` を `self._U_H_half @ rho @ self._U_H_half.conj().T` に置換
3. `_apply_lindblad_stinespring` を `apply_stinespring_to_density_matrix(rho, self._U_stines[k])` に置換
4. Hamiltonianステップ後のディフェージングを追加（ショットベースと整合させる）

### 4.2 検証スクリプトの修正

`test_noise_channel_verification` の解析的パスを修正し、Trotterステップ内でノイズを交互に適用するようにする。
