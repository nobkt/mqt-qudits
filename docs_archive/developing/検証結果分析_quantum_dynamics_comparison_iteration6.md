## 2. 発見された問題

### 問題1: 脱分極率のドキュメント不整合（重大度: 中）

**現象**: コードで使用する値（0.001 = 0.1%）とドキュメントの記述（0.01 = 1.0%）が一致しない。

| 場所 | 現在の値 | ドキュメント記述 |
|------|---------|----------------|
| GKSL Cell 33 (markdown) | - | `$p_{depol}=0.01$` (1.0%) |
| GKSL Cell 34 (code) | `p_depol=0.001` (0.1%) | - |
| GKSL Cell 37 (markdown) | - | `$p_{depol}=0.01$` (1.0%) |
| GKSL Cell 38 (code) | `p_depol=0.001` (0.1%) | - |
| Complete Cell 15 (code) | `depol_2q=0.001` | コメント: "1.0%" |
| Complete Cell 23 (code) | `depol_2q=0.001` | コメント: "1.0%" |

**修正方針**: コード値 `0.001` をユーザーの意図的な選択として尊重し、ドキュメントとコメントを `0.001` (0.1%) に統一。

### 問題2: Qubitノイズシミュレータのノイズ粒度が根本的に間違っている（重大度: 致命的）

**これが本報告で発見された最も重要な問題である。**

**現象**: `qubit_noisy_simulator.py` は Qiskit Aer を使用してゲートレベルでノイズを適用している。一方、`mqt_qudits_noisy_simulator.py` はペアゲートレベルで密度行列にノイズを適用している。

#### ノイズ粒度の比較

| シミュレータ | ノイズ適用レベル | 1ステップあたりノイズイベント数 | 手法 |
|------------|----------------|-------------------------|------|
| `qubit_noisy_simulator.py` | **個別CXゲートレベル** | **~814** | Qiskit Aer + NoiseModel |
| `mqt_qudits_noisy_simulator.py` | ペアゲートレベル | **12** | 密度行列 + 解析的チャネル |
| `qubit_gksl_shot_simulator.py` | ペアゲートレベル | ~6-12 | 純粋状態軌道 + Pauli確率 |

**根本原因の詳細**:

1. `qubit_noisy_simulator.py` の `build_single_trotter_step()` は UnitaryGate を使用して回路を構築
2. UnitaryGate は Qiskit Aer transpile 時に基本ゲート（CX, RZ等）に分解される
3. 分解後、1トロッターステップに **814個の CX ゲート** が生成される
4. `AerSimulator` の `NoiseModel` は **各 CX ゲートに独立して** 脱分極ノイズを適用
5. 100ステップ × 814 CX = **81,400回のノイズイベント**

一方、物理的に意味のあるノイズイベント（ハミルトニアン相互作用ペア）は **12回/ステップ**（3ペア × 2ハーフステップ × 2種類(transfer+TTA)）のみ。

#### ノイズ蓄積の数学的分析

**Qubit（現行、CXゲートレベルノイズ）:**

各CXゲートの脱分極確率 $p = 0.001$、2-qubit脱分極チャネル:

$$\varepsilon(\rho) = (1-p)\rho + \frac{p}{4} I_4$$

CXゲートは2量子ビット（4次元空間）に作用。物理状態は3/4（|00⟩, |01⟩, |10⟩）。各CXノイズイベントで非物理状態 |11⟩ への漏れ確率 $\approx p/4$。

100ステップ × 814 CX = 81,400ノイズイベント → 累積非物理リーケージ → 壊滅的。

**Qudit（ペアゲートレベルノイズ）:**

各ペアゲートの脱分極確率 $p = 0.001$、2-qutrit脱分極チャネル:

$$\varepsilon(\rho) = (1-p)\rho + p \cdot \text{Tr}_{ij}(\rho) \otimes I_9/9$$

全ての9状態が物理的に有効 → **リーケージなし**。

12ノイズイベント/ステップ × 100ステップ = 1,200イベント → 適度なデコヒーレンスのみ。

#### 数値的検証

| 指標 | Qubit現行 | Qudit | Qubit修正後（理論予測） |
|------|----------|-------|---------------------|
| ノイズイベント/ステップ | 814 | 12 | 12 |
| 非物理的状態 (最終) | **69.1%** | **0%** | **~40%** |
| N_T1 (最終) | 0.406 | 1.298 | ~0.45 |
| 粒子数保存 | 1.24/4.0 | 4.0/4.0 | ~2.3/4.0 |

**注**: 修正後もQubit encodingでは $I_{16}/16$ の $7/16$ が非物理状態であるため、約40%のリーケージは**量子ビット符号化の物理的限界**として残る。これはバグではなく、Qubitエンコーディングの本質的な特性である。

### 問題3: Qubitエンコーディングの固有のリーケージ（重大度: 情報提供）

Qubitエンコーディング（d=4、2量子ビット/分子）の脱分極ノイズでは:
- ペアの $I_{16}/16$（最大混合状態）の $7/16 = 43.75\%$ が非物理状態
- これは符号化方式の物理的制約であり、バグではない
- GKSL Cell 38の43.6%リーケージはこの理論値と整合
- Quditエンコーディング（d=3）では全状態が物理的であり、リーケージ=0

**この差異は、Quditエンコーディングの利点を示す重要な結果**であり、ノートブックの結論を支持する。

    H_TTA(dt/2):  reverse                  ← ペアレベルノイズ（3ペア）
    H_transfer(dt/2): reverse              ← ペアレベルノイズ（3ペア）

**脱分極チャネル**:
$$\varepsilon(\rho) = (1-p)\rho + p \cdot \text{Tr}_{ij}(\rho) \otimes \frac{I_{16}}{16}$$

ここで $d = 4$（2量子ビット/分子）、$d^2 = 16$（ペア次元）。

## 5. 技術的根拠

### 5.1 なぜQiskit Aerのゲートレベルノイズが不適切か

Qiskit Aer のノイズモデルは **量子ハードウェアの物理的エラー** をシミュレートする。各ネイティブゲート（CX, RZ等）に独立したエラーが発生する。

しかし、このノートブックの目的は **量子ビットエンコーディングと量子トリットエンコーディングの比較** である。比較のために必要なのは:
- 同一の **論理ゲート**（ハミルトニアン相互作用）に同一のノイズを適用すること
- ゲート分解の詳細（CXの数）に依存しないこと

UnitaryGate → CX分解では、1つの論理的な2分子相互作用が ~68個の CX ゲートに分解される。各 CX にノイズを適用すると、論理ゲートあたりのノイズが ~68倍になり、Qudit（分解なし、CExゲート1個）との比較が不公平になる。

### 5.2 密度行列ペアレベルノイズの正当性

$\varepsilon(\rho) = (1-p)\rho + p \cdot \text{Tr}_{ij}(\rho) \otimes I_{d^2}/d^2$ は:
- 完全正値（CP）かつトレース保存（TP）な量子チャネル
- Weyl-Heisenberg Kraus分解と数学的に等価
- GKSL qubit shot simulator（`qubit_gksl_shot_simulator.py`）と同一のノイズモデル
- Qudit noisy simulator（`mqt_qudits_noisy_simulator.py`）と同一のノイズ粒度

### 5.3 リーケージの物理的解釈

Qubitエンコーディングのリーケージは **実際のハードウェアでも起こりうる現象** である:
- 物理量子ビットの脱分極は全計算基底状態に均等に散乱する
- |11⟩ 状態は Qubit encoding では禁止だが、ハードウェアレベルでは有効な状態
- よって、リーケージは Qubit encoding の **真の物理的制約** を正しく反映している
