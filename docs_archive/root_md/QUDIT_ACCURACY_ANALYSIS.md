# Qudit量子回路精度問題の詳細分析

## 問題の概要

tutorials/quantum_dynamics_complete_comparison.ipynbを実行する際に、以下の結果が観測されました：

**20fs時間発展の結果：**
- **Qubit実装**: 2656ゲート/トロッターステップ、誤差 ~0.01-0.02（最大）
- **Qudit実装**: 118ゲート/トロッターステップ、誤差 ~0.23（最大）← **1桁以上悪い**

量子ゲート数が1/22に削減されているにもかかわらず、Qudit実装の精度が著しく悪化している原因を分析しました。

---

## 根本原因の特定

### 1. H_TTA分解における重大なバグ

`tutorials/exact_qudit_basic_gates.py`のH_TTA（三重項-三重項消滅）ハミルトニアンの時間発展演算子に**数学的に誤った行列**が実装されていることが判明しました。

#### 問題のコード（94-107行目）

```python
def apply_H_TTA_basic_gates(circuit, qudit_i: int, qudit_j: int,
                             J: float, dt: float, hbar: float):
    omega = np.sqrt(2) * J * dt / hbar
    cos_omega = np.cos(omega)
    sin_omega = np.sin(omega)
    
    # WRONG FORMULA - この行列はユニタリではない！
    U_TTA = (1/2) [[1+cos(ω),  √2·sin(ω),  1-cos(ω)],
                   [√2·sin(ω), 2·cos(ω),    √2·sin(ω)],
                   [1-cos(ω),  √2·sin(ω),  1+cos(ω)]]
```

#### 数値検証結果

テストパラメータ（J=0.05 eV, dt=10 fs, ℏ=0.6582 eV·fs）での検証：

**誤った行列（コード内）:**
```
[[0.738, 0.622, 0.262],
 [0.622, 0.476, 0.622],
 [0.262, 0.622, 0.738]]
```

**ユニタリ性チェック:** U†U を計算
```
[[1.000, 0.918, 0.773],    ← 対角要素以外が0でない！
 [0.918, 1.000, 0.918],
 [0.773, 0.918, 1.000]]
```

**ユニタリ性誤差: 2.14** ← これは許容範囲（~10^-10）を大幅に超えています！

#### 正しい行列

scipy.linalg.expm(-iH·t/ℏ)による厳密計算：

**H_TTA ハミルトニアン** (3×3部分空間 {|02⟩, |11⟩, |20⟩}):
```
H = J [[0, 1, 0],
       [1, 0, 1],
       [0, 1, 0]]
```

**固有値**: E = {-√2·J, 0, +√2·J} = {-0.0707, 0, 0.0707} eV

**正しいユニタリ行列:**
```
U_correct = [[ 0.738+0j,      0-0.622j,  -0.262+0j  ],  ← 注意: U[0,2]は負
             [ 0-0.622j,   0.476+0j,      0-0.622j  ],
             [-0.262+0j,      0-0.622j,   0.738+0j  ]]  ← 注意: U[2,0]は負
```

**ユニタリ性誤差: 4.3×10^-16** ← 機械精度レベル（正常）

### 2. バグの詳細

#### 誤りの種類

オフ対角要素が**実数であるべきところを虚数**として実装されています：

| 位置 | 誤った値（コード） | 正しい値 |
|------|-------------------|----------|
| (0,1), (1,0) | **+0.622** (実数) | **-0.622j** (純虚数) |
| (1,2), (2,1) | **+0.622** (実数) | **-0.622j** (純虚数) |

この誤りにより、行列がユニタリ性を失い、時間発展が物理的に正しくない演算となっています。

#### 影響範囲

1. **ユニタリ性の破綻**: ノルム保存が崩れ、確率解釈が成立しない
2. **時間発展の誤り**: 各トロッターステップで誤差が蓄積
3. **精度の大幅悪化**: 20fsの時間発展で誤差が1桁以上悪化

## 精度悪化のメカニズム

### 1. トロッター分解における誤差蓄積

時間発展は鈴木トロッター分解により実装：

```
U(t) ≈ [U_H0(δt) · U_transfer(δt) · U_TTA(δt)]^N
```

ここで、
- N_steps = t / δt = トロッターステップ数
- 20fs時間発展では、複数ステップ必要

**各ステップでの誤差:**
- H0: 正確（対角行列、位相回転のみ）
- H_transfer: 正確（2×2部分空間、CExゲートで厳密実装）
- **H_TTA: 非ユニタリ行列により誤差発生** ← ここが問題！

### 2. ゲート数と精度の関係

**一般的な理解（誤解）:**
- ゲート数が少ない → 精度が高い

**実際の状況:**
- ゲート数: Qudit (118) < Qubit (2656)  ✓
- **しかし**: Quditの基本ゲート分解に数学的誤りがある
- 結果: ゲート数は少ないが、各ゲートが誤った演算を実行

**類推:** 
- 正しい100ステップの計算 vs 誤った10ステップの計算
- ステップ数が少なくても、各ステップが誤っていれば結果も誤る

## Qudit量子回路が基本ゲートで厳密に分解できているか？

### 1. H_transfer（エネルギー移動項）

**結論: 厳密に分解できている ✓**

実装方法:
```python
# 2D部分空間 {|01⟩, |10⟩} での回転
# CEx（制御励起）ゲート + VirtRz（仮想Z回転）ゲート

circuit.virtrz(qudit_i, [1, -π/2])     # 位相調整
circuit.virtrz(qudit_j, [0, -π/2])     
circuit.cx([qudit_i, qudit_j], [0, 1, 0, θ])  # 主回転
circuit.cx([qudit_j, qudit_i], [0, 1, 0, θ])  # 対称性
circuit.virtrz(qudit_i, [1, π/2])      # 位相補正
circuit.virtrz(qudit_j, [0, π/2])
```

検証結果:
- ユニタリ性誤差: < 10^-12
- 理論との一致: 厳密

### 2. H_TTA（三重項-三重項消滅項）

**結論: 分解できていない ✗ - 数学的誤りあり**

実装方針（コード内のコメント）:
```python
# 3D部分空間 {|02⟩, |11⟩, |20⟩} での回転
# Givens回転分解 → VirtRz, R, CEx ゲート
```

**問題点:**
1. ターゲットユニタリ行列の定義が誤っている
2. 非ユニタリ行列を基本ゲートに分解しようとしている
3. Givens回転角度の計算式が誤っている

現状の実装:
```python
# Line 104-107: 誤った行列定義
U_TTA = (1/2) [[1+cos(ω),  √2·sin(ω),  1-cos(ω)],
               [√2·sin(ω), 2·cos(ω),    √2·sin(ω)],
               [1-cos(ω),  √2·sin(ω),  1+cos(ω)]]
# ← この行列はユニタリではない！
```

正しい実装（scipy.linalg.expm使用）:
```python
H = J * np.array([[0, 1, 0],
                  [1, 0, 1],
                  [0, 1, 0]])
U_TTA_correct = scipy.linalg.expm(-1j * H * dt / hbar)
# ← 対角要素は実数、オフ対角要素は純虚数
```

**確認結果: CustomTwoゲートは使用されていない ✓**

コード調査:

- H_transfer: 直接CExゲートで実装
- H_TTA: 直接Givens分解（ただし、ターゲット行列が誤り）

**しかし**: CustomTwoゲートを使わないこと自体は正しい方針ですが、手動で分解したユニタリ行列が数学的に誤っているため、結果として精度が悪化しています。

## まとめ

### 質問1: なぜQuditの方が1桁以上精度が悪くなったか？

**回答:**

Quditの実装において、H_TTA（三重項-三重項消滅）ハミルトニアンの時間発展演算子が**数学的に誤った行列**で実装されているためです。

**具体的な原因:**
1. `exact_qudit_basic_gates.py`の94-107行目で定義されたユニタリ行列が、実際にはユニタリではない（ユニタリ性誤差: 2.14）
2. オフ対角要素が純虚数であるべきところを実数として実装
3. 各トロッターステップで非ユニタリ演算が実行され、誤差が蓄積
4. 20fs時間発展では複数のトロッターステップを経るため、誤差が指数的に増大

**ゲート数との関係:**
- ゲート数が少ないこと自体は利点
- しかし、各ゲートが誤った演算を実行していれば、ゲート数の少なさは無意味
- 正しいQudit実装（修正後）では、ゲート数が少なく、かつ精度も高くなるはず

### 質問2: Qudit量子回路は基本ゲートで厳密に分解できているか？

**回答:**

**部分的にYES、部分的にNO:**

**厳密に分解できている部分:**
- ✓ H0（対角項）: VirtRzゲートで厳密実装
- ✓ H_transfer（エネルギー移動）: CExゲート + VirtRzで厳密実装
- ✓ CustomTwoゲート不使用: すべて基本ゲート（VirtRz, R, Rz, Rh, CEx）で実装

**分解できていない部分:**
- ✗ H_TTA（三重項-三重項消滅）: **ターゲットユニタリ行列の定義に数学的誤りあり**
  - コード内の行列はユニタリではない
  - 結果として、基本ゲートへの分解も誤っている

**結論:**
現在の実装では、H_TTAの部分で数学的誤りがあるため、「厳密な基本ゲート分解」は達成されていません。しかし、これは実装バグであり、理論的には可能です。

## 修正方針

### 1. 即座の修正（H_TTA行列の訂正）

`exact_qudit_basic_gates.py`を以下のように修正しました：

#### 修正前（誤り）:
```python
# Lines 105-107: 誤った行列定義（非ユニタリ）
U_TTA = 0.5 * np.array([
    [1 + cos_omega, np.sqrt(2) * sin_omega, 1 - cos_omega],      # ← 全て実数（誤り）
    [np.sqrt(2) * sin_omega, 2 * cos_omega, np.sqrt(2) * sin_omega],
    [1 - cos_omega, np.sqrt(2) * sin_omega, 1 + cos_omega]
])
# ユニタリ性誤差: 2.14 ← 許容範囲外！
```

#### 修正後（正しい）:
```python
# scipy.linalg.expmを使用した厳密計算
from scipy.linalg import expm

H_TTA = J * np.array([[0, 1, 0],
                      [1, 0, 1],
                      [0, 1, 0]])
U_TTA = expm(-1j * H_TTA * dt / hbar)
# ユニタリ性誤差: < 1e-15 ← 機械精度レベル（正常）

# または、解析的に:
omega = np.sqrt(2) * J * dt / hbar
U_TTA = np.array([
    [0.5*(1+cos(omega)),  -1j*sin(omega)/np.sqrt(2),  -0.5*(1-cos(omega))],  # ← 虚数部あり、符号注意
    [-1j*sin(omega)/np.sqrt(2),  cos(omega),  -1j*sin(omega)/np.sqrt(2)],
    [-0.5*(1-cos(omega)),  -1j*sin(omega)/np.sqrt(2),  0.5*(1+cos(omega))]
])
# ユニタリ性誤差: < 1e-15 ← 正常
```

**重要な変更点:**
1. **scipy.linalg.expmを追加**: 数値的に厳密なユニタリ行列を計算
2. **オフ対角要素を純虚数に修正**: `√2*sin(ω)/2` → `-i*sin(ω)/√2`
3. **U[0,2], U[2,0]の符号を修正**: `+0.5*(1-cos(ω))` → `-0.5*(1-cos(ω))`
4. **ユニタリ性検証を追加**: 実行時にエラーチェック
