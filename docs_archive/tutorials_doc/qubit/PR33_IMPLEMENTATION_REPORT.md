## 2. 技術的詳細

### 2.1 使用技術

**Qiskitの標準機能のみを使用:**
- `QuantumCircuit.num_qubits`: Qubit数の取得
- `len(QuantumCircuit.data)`: ゲート数の取得
- `QuantumCircuit.depth()`: 回路深さの取得
- `QuantumCircuit.draw(output='text')`: テキスト形式の回路図生成
- `collections.Counter`: ゲートタイプの集計

**絶対に使用していない:**
- `scipy.linalg.expm`: 行列指数関数の直接計算
- 近似的な手法
- ヒューリスティックな処理
- fallbackメカニズム

### 2.2 実装方針

1. **厳密性の維持**: すべての計算はQiskitの組み込み関数を使用
2. **透明性**: ユーザーが回路の詳細を完全に把握できる情報を提供
3. **スケーラビリティ**: 異なる分子数でも容易に解析可能
4. **教育的価値**: QubitとQuditの違いを明確に示す

### 2.3 回路解析メソッド

#### Qubit数の計算
```python
n_qubits = params.N_molecules * 2
```
- 各分子を2 Qubitで表現
- エンコーディング: |S0⟩→|00⟩, |T1⟩→|01⟩, |S1⟩→|10⟩
- |11⟩は未使用状態

#### ゲート数の取得
```python
n_gates = len(circuit.data)
```
- 回路内のすべての命令をカウント
- 各命令は1つのゲート操作を表す

#### 回路深さの取得
```python
depth = circuit.depth()
```
- 回路の並列化を考慮した深さ
- 量子ハードウェアでの実行時間の指標

#### ゲートタイプの集計
```python
from collections import Counter
gate_types = Counter([inst.operation.name for inst in circuit.data])
```

## 3. 結果と考察

### 3.1 4分子系の詳細結果

#### システムリソース
- **Qubit数**: 8個（2個/分子）
- **状態空間**: 256次元（全体）、81次元（物理的）
- **効率**: 31.6%（68.4%が未使用）

#### 単一トロッターステップ
- **ゲート数**: 112個
- **回路深さ**: 26
- **ゲート内訳**:
  - X gate: 48個 (42.9%)
  - RZ gate: 30個 (26.8%)
  - CNOT (CX): 16個 (14.3%)
  - CRY gate: 12個 (10.7%)
  - RXX gate: 6個 (5.4%)

#### 全シミュレーション（20ステップ）
- **総ゲート数**: 2,240個
- **平均ゲート数/ステップ**: 112個

### 3.2 スケーリング特性

#### Qubit数のスケーリング
```
N_molecules:  2    3    4    5
Qubits:       4    6    8   10
関係式: n_qubits = 2 × N_molecules
```
**結論**: 完全な線形スケーリング

#### ゲート数のスケーリング
```
N_molecules:  2    3    4    5
Gates:       44   78  112  146
関係式: n_gates ≈ 34N - 24
```
**結論**: ほぼ線形スケーリング

#### 回路深さのスケーリング
```
N_molecules:  2    3    4    5
Depth:       18   26   26   28
```
**結論**: ほぼ一定（分子間相互作用が支配的）

#### 状態空間効率
```
N_molecules:  2      3      4      5
Efficiency:  56.2%  42.2%  31.6%  23.7%
```
**結論**: 分子数の増加とともに効率が低下

### 3.3 QubitとQuditの比較

#### 定量的比較（4分子系）

| 項目 | Qubit版 | Qutrit版 | 比率 |
|------|---------|----------|------|
| Qudit数 | 8 | 4 | 2.0× |
| 状態空間次元 | 256 | 81 | 3.16× |
| 物理的次元 | 81 | 81 | 1.0× |
| ゲート数/ステップ | 112 | ~55* | ~2.0× |
| 状態空間効率 | 31.6% | 100% | - |

*Qutrit版のゲート数は既存プロジェクトドキュメント (tutorials/qubit/README.md) からの推定値

#### 定性的比較

**Qubit版の利点:**
- ✅ 広く利用可能なハードウェア（IBM Quantum, Rigetti, IonQ等）
- ✅ 成熟したツールチェーン（Qiskit, Cirq等）
- ✅ 豊富な学習リソースとコミュニティサポート
- ✅ 実機での実行が現時点で可能

**Qubit版の欠点:**
- ❌ 状態空間の68%が未使用（リソースの無駄）
- ❌ ゲート数が約2倍
- ❌ より複雑な状態管理

**Qutrit版の利点:**
- ✅ 自然な状態表現（3準位→3準位）
- ✅ 高いゲート効率（約2倍速い）
- ✅ すべての状態が物理的意味を持つ
- ✅ より小さいリソース要件

**Qutrit版の欠点:**
- ❌ ハードウェアが実験段階
- ❌ ツールチェーンが発展途上
- ❌ 限定的なコミュニティサポート
- ❌ 現時点では実機での実行が困難
