# 4分子線形鎖モデル量子ダイナミクスにおけるQudit実装の計算コスト問題

## 問題の概要

4分子直鎖配置モデルの量子ダイナミクスシミュレーションにおいて、Qudit実装とQubit実装で大幅な計算コスト（ゲート数）の差が観測されました。

### 実測結果

**Qubit実装** (`tutorials/qubit/four_molecule_linear_chain_quantum_dynamics_qubit.ipynb`):

```
Qubit数: 8 (4分子 × 2 qubit/分子)
単一トロッターステップのゲート数: 44
回路深さ: 18
```

**Qudit実装** (`tutorials/four_molecule_linear_chain_quantum_dynamics.ipynb`):

```
分解前のゲート数: 14
  - H0の時間発展: 8個のVirtRzゲート
  - H_transferの時間発展: 3個のCustomTwoゲート
  - H_TTAの時間発展: 3個のCustomTwoゲート

分解後のゲート数: 6,182
  - CEx: 1,062個
  - R: 1,560個
  - Rh: 1,632個
  - Rz: 1,266個
  - VirtRz: 662個
```

### ゲート数の比較

- Qubit実装: **44ゲート**
- Qudit実装: **6,182ゲート**
- 差: **約140倍**

この圧倒的な差は、Qudit実装に何か根本的な問題があることを示唆しています。

## 原因の特定

### 根本原因: CustomTwoゲートの非効率的な分解

詳細な分析により、以下のことが判明しました：

1. **単一CustomTwoゲートの分解コスト**

   - 1個のCustomTwo（9×9ユニタリ行列）→ 約1,000個の基本ゲート
   - 測定値: 966ゲート（CEx: 166, R: 244, Rh: 256, Rz: 198, VirtRz: 102）

2. **分解アルゴリズムの特性**

   - 使用されるコンパイラ: `LogEntQRCEXPass`
   - 手法: QR分解ベースの一般的なユニタリ分解
   - 計算量: O(d²) × 10ゲート程度、d=9の場合 ≈ 810-1000ゲート

3. **疎構造の無視**
   - H_transfer: 9×9行列のうち非自明な要素はわずか4個（2×2部分空間のみ）
   - H_TTA: 9×9行列のうち非自明な要素はわずか9個（3×3部分空間のみ）
   - 残りの要素は単位行列（恒等変換）
   - **しかし、分解アルゴリズムはこの構造を一切活用していない**

### 具体例: H_transferのユニタリ行列

```
基底順序: |00⟩, |01⟩, |02⟩, |10⟩, |11⟩, |12⟩, |20⟩, |21⟩, |22⟩

[[1,    0,       0,    0,       0, 0, 0, 0, 0],   # |00⟩
 [0,  cos(θ),    0, -i·sin(θ),  0, 0, 0, 0, 0],   # |01⟩ ← 作用
 [0,    0,       1,    0,       0, 0, 0, 0, 0],   # |02⟩
 [0, -i·sin(θ),  0,  cos(θ),    0, 0, 0, 0, 0],   # |10⟩ ← 作用
 [0,    0,       0,    0,       1, 0, 0, 0, 0],   # |11⟩
 [0,    0,       0,    0,       0, 1, 0, 0, 0],   # |12⟩
 [0,    0,       0,    0,       0, 0, 1, 0, 0],   # |20⟩
 [0,    0,       0,    0,       0, 0, 0, 1, 0],   # |21⟩
 [0,    0,       0,    0,       0, 0, 0, 0, 1]]   # |22⟩
```

**観察**:

- 非自明な要素: 4個のみ（位置 [1,1], [1,3], [3,1], [3,3]）
- これは実質的に2×2回転を9×9空間に埋め込んだもの
- 理論的には8-15ゲートで実装可能
- **実際の分解: 966ゲート（約65-120倍の無駄）**

## なぜ最適化が困難か

### MQT-Quditsフレームワークの制約

1. **一般性重視の設計**

   - 任意のqudit操作をサポートするよう設計
   - 特殊な構造を持つ操作への最適化は考慮されていない

2. **APIの制約**

   - 基本ゲート（CEx, R, Rh, Rz）を直接組み合わせる方法が複雑
   - 高レベルAPI（cu_two等）はCustomTwoゲートを経由
   - CustomTwoを使う限り、LogEntQRCEXPassによる分解は避けられない

3. **実装の複雑さ**
   - 疎構造を活用した直接実装には、100行以上の複雑なゲートシーケンス生成コードが必要
   - 既存のCRotGen等の実装を見ると、非常に高度な技術が要求される

### 部分最適化の試行結果

グローバル位相の除去など、簡単な最適化を試みましたが：

```

最適化試行: 12,368ゲート
改善率:     0%
```

CustomTwoゲートを使用する限り、改善は不可能でした。

2. **副次的要因（寄与度10%）**: QuditゲートがQubitゲートより本質的に複雑
